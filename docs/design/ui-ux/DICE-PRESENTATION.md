# SimpleVTT 주사위 연출 계약

Status: **OWNER-DIRECT REVIEWED PRODUCT DIRECTION — ACTIVE PRESENTATION CONTRACT**

Updated: **2026-08-22**

Owner clarification:

> 주사위끼리도 충돌은 가능해야하는데 꼭 의도할 필요는 없어.
> 주사위 트레이는 따로 안만들고 화면이 주사위 트레이가 될거야. 테이블에 던진다는 공간감은 화면을 테이블로써 여기고 던지게 되는걸꺼야.
> 아마도 내가 이전에 한 말을 AI가 왜곡해서 저장한것일 가능성이 높아. 앞으로 발견하는 충돌은 웬만하면 최신 문서를 기준으로 작업하면 돼.

이 문서는 주사위 연출에 관한 과거 AI 요약/에이전트 문서의 왜곡 가능성을 교정한다. 동일한 표현 계층의 이전 문서와 충돌하면 이 문서와 더 최신의 명시적 Owner 방향을 우선한다. 단, Domain/Architecture의 권위·결과 결정·네트워크 일관성 계약은 프레젠테이션 문서보다 계속 우선한다.

---

# 1. 공간 모델

주사위 연출에서 **화면 자체가 테이블이자 주사위 트레이**다.

별도의 시각적 Dice Tray, 테두리 박스, 나무/가죽 트레이, 독립된 미니게임 영역을 만들지 않는다.

사용자는 현재 SimpleVTT 화면의 플레이 평면 자체를 테이블로 인식해야 한다.

```text
현재 화면 / Play surface
= 주사위를 던지는 테이블
= 주사위가 머무는 물리 공간
= 별도 tray UI 없음
```

필요한 물리 경계는 주사위가 화면 밖으로 영구 이탈하지 않도록 보이지 않는 충돌 경계로 구현할 수 있다. 이 경계는 별도의 시각적 트레이를 의미하지 않는다.

---

# 2. 투척 감각

주사위는 화면 위에 단순히 생성되어 제자리 회전하거나 위에서 아래로 떨어지는 UI 오브젝트처럼 보여서는 안 된다.

기존 최신 방향의 핵심은 유지한다.

1. 주사위가 화면의 깊이/뒤쪽에서 작은 크기로 등장할 수 있다.
2. 빠른 초기 선속도와 각속도를 가진다.
3. 화면을 테이블 평면으로 인식시키는 방향으로 실제 rigid-body 투척을 한다.
4. 테이블 평면에 충돌한다.
5. 짧게 튀고 구르며 회전한다.
6. 마찰과 감쇠로 자연스럽게 속도를 잃는다.
7. 결과가 읽히는 안정된 자세로 정지한다.

중요한 것은 특정 카메라 궤적을 영화처럼 재생하는 것이 아니라 **실제 물체를 화면이라는 테이블에 던졌다는 감각**이다.

---

# 3. 주사위끼리의 충돌

여러 개의 주사위를 동시에 굴릴 때 주사위는 서로 실제 물리 충돌이 가능해야 한다.

예:

```text
4d6
-> d6 네 개가 같은 물리 월드에 존재
-> 서로 접촉하면 충돌 응답 발생 가능
```

그러나 주사위끼리 부딪히는 장면을 의도적으로 연출하거나 매번 충돌하도록 초기 궤적을 조작하지 않는다.

즉:

- dice-dice collision: **지원한다**;
- scripted/choreographed collision: **요구하지 않는다**;
- 충돌 횟수를 시각적 품질 지표로 사용하지 않는다;
- 자연스럽게 충돌하지 않는 정상적인 굴림도 허용한다.

충돌은 실제 물리 월드의 자연스러운 결과여야 한다.

---

# 4. 화면 경계

별도 Dice Tray 모델을 만들지 않는다.

대신 현재 렌더 영역/안전 영역을 하나의 물리적 테이블 공간으로 본다. 필요하면 보이지 않는 경계 collider를 사용하여 주사위가 화면 밖으로 빠져 결과를 읽을 수 없게 되는 것을 방지한다.

경계 충돌 역시 과장된 연출 목표가 아니다.

```text
주사위 -> 화면 안에서 자연스럽게 이동
주사위 -> 경계와 실제로 접촉하면 반응 가능
하지만
'벽에 한 번 부딪힌 뒤 중앙으로 와야 한다' 같은 연출 규칙은 없음
```

---

# 5. 물리와 결과 권위

주사위 연출은 실제 WebGL polyhedral geometry와 rigid-body physics를 사용한다.

지원 기본 주사위:

- d4
- d6
- d8
- d10
- d12
- d20

필요한 경우 동일 구조로 다른 geometry를 추가할 수 있어야 한다.

물리 연출과 게임 결과 권위는 분리한다.

- Standalone/local roll은 정해진 로컬 roll authority를 따른다.
- Connected Session의 결과는 Host-authoritative 결과를 따른다.
- 네트워크 게임에서 화면의 물리 시뮬레이션이 게임 결과를 새로 결정하지 않는다.
- 시각 주사위는 이미 결정된 authoritative raw result와 모순되지 않도록 최종적으로 수렴/표시한다.

주사위끼리의 충돌, 바닥 접촉, 화면 경계 접촉이 authoritative 결과를 임의로 바꾸는 두 번째 게임 규칙 엔진이 되어서는 안 된다.

---

# 6. 속도와 리듬

주사위는 실제 물리감을 가지되 일상 판정을 느리게 만드는 긴 시네마틱이 되어서는 안 된다.

현재 목표:

```text
일반 roll trigger -> 읽을 수 있는 settled result
약 1.0 ~ 1.4초 목표
1.5초를 routine UX 상한으로 사용
```

이 값은 물리 테스트 과정에서 손맛을 위해 미세 조정할 수 있지만, 느린 장식 연출이 플레이 흐름을 압도해서는 안 된다.

Reduced Motion은 더 짧고 작은 움직임을 사용하되 결과는 동일하게 읽을 수 있어야 한다.

---

# 7. 결과 UI

3D 주사위는 결과를 읽는 유일한 수단이 아니다.

기존 방향대로 화면 상단 중앙 부근의 compact result presentation을 유지할 수 있다.

- 굴리는 동안: 행동/굴림명 + 주사위 종류 + presentation-only raw numeral reel;
- 정지 시: authoritative raw result에서 멈춤;
- 이후 modifier/formula/final total을 확장 표시;
- Natural 20은 semantic green;
- Natural 1은 semantic red;
- semantic color는 사용자 accent보다 우선.

Tauri 주사위 샌드박스의 첫 단계에서는 결과 패널보다 **물리 투척 감각**을 먼저 검증해도 된다.

---

# 8. Tauri 단독 테스트 기준

SimpleVTT 전체 UI에 다시 붙이기 전에 주사위만 독립적으로 검증하는 Tauri sandbox를 사용한다.

첫 샌드박스의 목적은 다음 질문에 답하는 것이다.

1. 화면 자체가 테이블처럼 느껴지는가?
2. 주사위가 실제 물체처럼 던져지는가?
3. 충돌/바운스/롤/마찰/감속이 자연스러운가?
4. d4/d6/d8/d10/d12/d20의 크기와 질량감이 서로 납득 가능한가?
5. 여러 주사위가 같은 월드에서 자연스럽게 공존하고 필요할 때 서로 충돌하는가?
6. 1~1.5초 안에서도 너무 가볍거나 인위적으로 보이지 않는가?
7. 주사위가 화면 밖으로 유실되지 않으면서도 보이지 않는 경계가 트레이처럼 인식되지 않는가?

첫 테스트에서는 Session, Actor, Command Center, 공격 VFX 등 다른 제품 요소를 섞지 않는다.

---

# 9. 문서 충돌 처리

주사위 연출처럼 과거 AI 요약/에이전트 기록과 최신 Owner 방향이 충돌할 경우:

```text
canonical Domain / Architecture authority
        ↓
최신 명시적 Owner product direction
        ↓
최신 canonical design document
        ↓
이전 product/design document
        ↓
과거 .agents / rerun / summary / prototype evidence
```

특히 과거 문서가 Owner 의도를 더 강한 요구로 확대하거나, 반대로 세부 요구를 누락한 흔적이 있으면 오래된 문구를 기계적으로 보존하지 않는다.

같은 권위 수준의 표현/UX 문서끼리 충돌한다면 **더 최신의 명시적 방향을 기본값으로 사용**한다.

---

# 10. 현재 교정된 요약

```text
화면 = 테이블 = 주사위가 굴러가는 공간
별도 Dice Tray UI 없음
실제 polyhedral rigid-body physics
바닥 충돌 / bounce / roll / 감속
여러 주사위는 같은 물리 월드에서 서로 충돌 가능
하지만 충돌 장면을 의도적으로 연출하지 않음
보이지 않는 화면 경계 collider 허용
routine roll은 빠르게
connected result authority와 presentation physics는 분리
```

이 요약을 앞으로 Tauri 주사위 샌드박스와 SimpleVTT 통합 시 기본 프레젠테이션 기준으로 사용한다.
