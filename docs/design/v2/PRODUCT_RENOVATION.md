## 1. 사용자가 확정한 제품 기준

- 한국어 D&D 중심 VTT. 범용 TRPG 플랫폼을 먼저 만드는 것이 목표가 아니다.
- Theater of the Mind로도 플레이가 완결되어야 한다. 좌표·거리 계산·지도 배치를 필수로 하지 않는다.
- 기존 교전/물러남/기회공격 설계를 유지한다. 피트 단위 거리 입력을 복원하지 않는다.
- 전투의 조작과 대기 시간을 줄인다. 계산 자동화가 플레이어의 결정을 대신하지는 않는다.
- 화려한 주사위·공격·주문·피해 이펙트가 필요하다. 화려함과 다음 조작의 반응성은 함께 확보한다.
- D&D의 자유 행동을 유지한다. 물건 버리기·던지기·엎드리기 등을 미리 만들어진 공격 목록만으로 제한하지 않는다.
- **세션에 참여하지 않은 개인 시트**에서 HP, 자원, 슬롯, 아이템 등을 편하게 수정한다.
  이 요구를 연결 중 플레이어의 임의 상태 변경 권한으로 확대 해석하지 않는다.
- 세션뿐 아니라 생성·시트·레벨업과 관련 시스템 전반이 개편 대상이다.
- 기술 선택은 조사 근거로 제안하고, 실제 사용 방식에 큰 영향을 주는 질문만 모아서 묻는다.

## 4. 상태를 ‘하나의 거대한 객체’ 대신 수명과 권한으로 나눈다

필드마다 한 시점에 하나의 쓰기 권위만 갖는다. 저장용 모델, 계산 결과, 화면 상태를 중복된 원본으로 취급하지 않는다.

1. **CharacterDocument — 개인 저장본:** 이름·콘텐츠 선택·레벨별 선택 기록·아이템 인스턴스·사용자가 작성한 기본 능력치와 레벨별 HP 선택.
   개인 사용 상태(HP/자원/슬롯/충전/수량)는 같은 문서의 명시적인 usage 영역이다.
   `buildRevision`과 `usageRevision`을 구분한다. 자동 계산된 AC/행동 목록은 저장 원본이 아니다.
2. **CharacterDraft — 생성/편집/성장 초안:** 기반 revision과 선택 변화. 자동 저장하되 확정본을 덮어쓰지 않는다.
   무효화된 선택은 원인과 재선택 위치를 보여준다. 취소/재시작 시 초안과 확정본이 구분된다.
3. **SessionState — 접속 중 권위:** Host가 확정한 actor 사용 상태·효과·교전·질문·장면·명령 기록.
   CharacterDocument의 동일 HP/아이템 필드를 동시에 별도 계산하지 않는다.
4. **View models:** 위 원본에서 계산한 시트·행동·결과·준비실 화면. 공개 범위에 맞는 데이터만 제공한다.
5. **UI state:** 선택 대상, 열린 탭, 검색어, 툴팁, 연출 재생 위치. 게임 상태/저장 데이터와 분리한다.

### 개인 수정 → 참여 → 종료

- 개인 수정은 로컬 명령으로 검증·저장한다. 세션을 임시 생성하거나 전투 자원을 소모하는 행동으로 가장하지 않는다.
- 참여 시 선택한 Character ID, revision, 콘텐츠 버전과 현재 상태를 넘긴다. 재접속은 새로운 입장/초기화가 아니다.
- 접속 중 같은 캐릭터의 개인 저장본 변경은 live actor를 자동 덮어쓰지 않는다. 편집한 초안은 분리하고
  Host와 호환되는 명시적 갱신 때만 적용한다.
- Host의 확정 사용 결과는 캐릭터 소유자에게 순서대로 저장 반영한다. 각 변경에는 session/epoch/command/event 식별자와
  기반 revision을 넣고, 재전송은 한 번만 적용한다. 확인 응답은 저장된 결과를 다시 반환한다.
- 끊긴 동안 개인 저장본을 고쳤다면 재접속 시 revision 충돌을 검출하고 차이를 제시한다.
  저장본·세션본 중 어느 쪽도 조용히 덮어쓰지 않는다. 최종 UX에서 복사본 보존 선택을 제공한다.
- 세션 종료와 비정상 종료 모두 저장 확인/미반영 상태를 구분한다. 저장 대기분은 재시작 후 복구한다.

## 5. 생성·편집·레벨업·개인 시트

### 공통 작성 기반

`기반 Character + 사용자 선택 + 고정한 콘텐츠 버전 → 선택 계획 + 파생값 + 검증 + 변경 미리보기`.
같은 클래스/주문/장비를 화면마다 서로 다르게 계산하지 않는다. 규칙별 선택 의존성은 기존 domain을 우선 재사용한다.
자동 획득은 자동으로, 사용자가 결정해야 하는 것만 질문한다. UI는 선택의 목록과 상태를 렌더링한다.

- 생성: 안내형/빠른 편집이 같은 초안을 사용. 종족·배경·클래스 변경 시 무관한 입력 유지.
- 성장: 필요한 새 선택만 제시하고 ‘바뀌는 것’을 비교. 저장은 한 번. 중간 저장 실패 시 반쪽 레벨업 없음.
- 높은 레벨 생성(D2): 원하는 시작 레벨을 선택하고 레벨별 progression 계산을 순서대로 실행하되 사용자는 하나의 묶인 작업으로 완료.
  멀티클래스의 획득 순서를 보존하고, 단순 `level=10` 복사로 처리하지 않음.
- 한국어 이름/검색/설명 우선, 영문명·출처는 보조. 미지원 콘텐츠는 설명 가능/수동 운용 가능/자동 실행 가능을 구분.

### 개인 시트

- HP는 숫자 입력과 `+/-`, 슬롯/직업 자원은 칸 클릭과 숫자 입력. 금화/아이템 수량/충전도 직접 수정.
- 규칙 행동인 ‘물약 사용’과 관리 작업인 ‘수량 3으로 수정’은 구분한다.
- 저장 실패는 값 옆에 표시하고 재시도·원래 값 복구. 성공하지 않았는데 저장됨으로 표시하지 않음.
- 현재 사용량의 직접 입력과 원본 설정 편집을 구분한다. 기본 능력치, 레벨별 HP 선택, 출처/빌드 등은
  **편집 버튼 → 초안 → 바뀌는 수치 비교 → 저장**으로 수정한다. 단순 사용량 수정 때 전체 생성기를 열지 않는다.
- AC, 능력 수정치, 명중 보너스, 주문 DC, 숙련 보너스 등 자동 계산 결과는 읽기 전용이다.
  계산된 최대 HP도 직접 덮어쓰지 않고 실제 기본값/성장 입력을 편집하여 재계산한다.
- `AC +2` 같은 임의 결과 오버라이드 편집 기능은 추가하지 않는다(D3). 장비/효과에 의한 정상적인 기여는 유지한다.
- 유한하지 않은 수치/잘못된 인스턴스 참조는 거부한다. 범위를 벗어난 사용량은 이유를 보여주고 원본 입력을
  수정할 경로를 제공하며, 사용자 입력을 몰래 잘라내거나 계산 결과를 덮어쓰지 않는다.
- 가방: 추가/검색/수량/충전/이름·메모/삭제·복구/장착·손 상태. 같은 아이템 정의의 여러 인스턴스를 구분.
- 개인 상태의 계산 확인용 굴림과 실제 세션 행동은 구분하되 결과를 읽는 방식은 통일한다.
- 디지털 탭 시트와 종이 시트 형태 중 선택할 수 있으며, 선택을 사용자 환경설정에 저장한다.
  두 화면은 같은 데이터/명령/권한을 사용한다. 별도의 캐릭터 모델이나 규칙 계산을 만들지 않는다.

## 6. 빠른 전투와 자유 행동

### 반복 행동

선택한 actor → 행동 → 대상 → 결과. 이전 대상·즐겨찾기·키보드 입력을 유지하고 추가 공격의 남은 횟수를 표시한다.
주사위는 자동 처리한다(D6). 슬롯 레벨/추가 자원/대상이 필요한 행동만 추가 선택. 반복 클릭·네트워크 재시도로 자원을 두 번 쓰지 않는다.
필수 선택 완료 전에는 피해/소비를 확정하지 않는다.

### 자유 행동

기본 빠른 항목: 손 비우기/꺼내기, 물건 놓기·줍기·전달, 던지기, 엎드리기/일어나기, 접근/물러남,
숨기·찾기·돕기·준비, 즉흥 행동 선언. 자유 진행과 이니셔티브에서 같은 actor 상태를 사용한다.

- ‘놓기’는 가방에서 삭제하는 것이 아니라 actor → 장면 바닥의 아이템 이동이다. 위치 좌표는 필요 없다.
- 투척 무기는 기존 공격 정의로 처리하고 인스턴스 수량/손 상태/회수 가능 상태를 함께 갱신한다.
- 임의 물건을 던져 피해를 내려 하면 DM 판정 경로로 보낸다. 묘사만 보고 피해 주사위·내성을 만들어내지 않는다.
- 엎드리기/일어서기는 자세 상태와 해당 D&D 비용 정책을 사용한다. 거리 숫자를 입력시키지 않는다.
- 선언만 있는 행동은 즉시 기록할 수 있고, 판정이 필요한 즉흥 행동은 DM이 DC·굴림·비용·결과를 지정한다.
- 기술적으로 미지원인 행동을 성공처럼 처리하지 않는다. DM이 수동 판정으로 처리할 명시적 경로는 항상 제공한다.
- 추가 공격처럼 일반 규칙상 불가한 행동은 DM의 명시적 허용으로 처리한다(D4).
  어떤 제약을 면제했는지, 실제 비용이 무엇인지 기록한다. 플레이어는 경고만 보고 강행할 수 없다.
  DM 예외도 소유권/연결 유효성/데이터 검증을 우회하지 않는다.

### 거리 없는 교전·기회공격

`docs/design/theater-of-mind-play.md`의 기존 정책을 기준으로 삼는다.
근접 공격은 명중/빗나감 모두 교전을 만든다. 기존 round 기반 교전 만료도 이식한다.
‘물러남’ 선언 시 실제로 반응할 수 있는 교전 상대에게만 기회공격 선택을 제시한다.
이탈의 억제·사망/장면 제거·교전 해제는 같은 규칙 경로에서 처리한다.
기존 설계를 D&D의 모든 공간 규칙을 정확히 자동화한 것으로 표시하지 않는다. ToTM 운용 정책임을 구분한다.

일반 사거리/시야는 기존의 허용 기본값과 DM 보정을 유지한다. DM에게 매번 거리·시야 확인을 요청하지 않는다.
비공개/불가시성, 자원 부족, 반응의 법적 타이밍 같은 명시적인 제약까지 ‘거리 생략’으로 지우지 않는다.
영역은 대상 선택·그룹과 DM 재량으로 처리하며 원/원뿔 좌표 배치를 요구하지 않는다.

### 반응과 사후 수정

- 방패/기회공격처럼 판정 결과를 바꾸는 반응은 해당 해결 단위만 잠깐 보류한다.
  시트 열기·설명 읽기·다음 행동 준비 등은 막지 않는다. 관련된 후속 명령은 확정 순서를 따른다.
- 질문은 적격자에게만 한 장. 비용과 대상, `사용 / 넘김`을 보여준다. 무응답 때문에 자동 포기하지 않는다. DM이 해당 질문을 넘길 수 있다(D5).
- 사후 보정은 기존 주사위 결과를 유지해 재계산한다. ‘새로 굴리기’는 별도 선택이다.
- 최근 독립 행동은 되돌릴 수 있지만, 그 아이템을 다른 사람이 이미 소비했다면 전체 과거 상태를 덮어쓰지 않는다.
  의존성에 맞는 보정 명령이나 보정 미리보기로 처리한다.

## 7. 화려하지만 기다리게 하지 않는 연출

- 명령 확정과 연출 완료를 분리한다. 연출 타이머가 공격/저장/네트워크 진행을 막지 않는다.
- 주사위·투사체·타격·치명타·피해 숫자·상태 변화는 한 resolution ID의 연출 묶음이다.
- 동시에 여러 결과가 오면 대상별 순서를 유지한다. 밀린 연출은 짧게 합쳐 보여주고 무한 재생 대기열을 만들지 않는다.
- 재접속의 과거 상태 재생은 과거 폭발 이펙트를 다시 재생하지 않는다. live 결과의 중복도 한 번만 보여준다.
- DM Only 결과는 수신자별로 필터한 후 연출한다. 숨은 대상의 위치/이름/피해를 이펙트로 누설하지 않는다.
- 현재 3D 주사위·공격 자산을 재사용하되 DOM selector 전역 검색보다 명시적 actor anchor 등록을 사용한다.
- 기본 비주얼 제안: 읽기 쉬운 어두운 판타지 화면 + 속성별 강한 색/궤적 + 뚜렷한 치명타/치유.
  강도 조절·음량·모션 축소를 제공. 화면 흔들림을 줄여도 명중/피해 정보는 남는다.
- 잠정 UX 예산: 로컬 입력 피드백 100ms 내, 일반 공격은 행동/대상 선택 후 추가 확인 0회,
  연출 때문에 생기는 입력 잠금 0ms. 프레임/네트워크 수치는 목표 기기에서 측정하고 아직 달성 주장하지 않는다.

## 8. DM 준비, 콘텐츠, 세션 외 흐름

- 캠페인 준비실에서 몬스터·NPC·아이템·자료를 검색하고 일괄 추가, 수량/그룹을 지정해 장면 묶음 저장.
- 진행 중 사이드바/통합 검색에서 꺼내고, 여러 대상에게 피해·상태·회복 적용. 선택과 검색 문맥 유지.
- 장면 전환은 actor 지속 상태·집중·소비 자원을 초기화하지 않는다. 장면 전용 효과의 수명은 별도 정의.
- 휴식·시간 경과·경험치/마일스톤·성장·파티 보관함은 캐릭터/세션과 같은 거래 경계를 따른다.
- 콘텐츠 추가는 간단한 사용자 아이템/메모와 고급 규칙 정의를 구분한다. 일반 사용자가 JSON을 써야만 등록되지 않게 한다.
- 한국어 콘텐츠 정의와 버전은 캐릭터/캠페인에 고정한다. 업데이트 때 출처·선택 ID를 몰래 교체하지 않는다.
- 외부 모듈의 자동 실행은 기존 검증/선언형 규칙 경계를 사용한다. 실행 불가여도 자료와 수동 판정은 가능하다.
- 연결/재접속, 최근 캠페인, 오류 복구, 백업/내보내기/가져오기, 첫 실행 안내까지 최종 수락 흐름에 포함한다.
- 기본 플랫폼은 기존 Windows 데스크톱/로컬 우선 흐름을 유지한다. 모바일 앱·클라우드 서비스·전술 지도 엔진을
  이번 결정으로 자동 추가하지 않는다. 좁은 창에서 화면 조작 가능성은 검증한다.

## 9. 내부 구조와 지속성

한 앱 안에 명시적인 기능 경계를 둔다. 새 마이크로서비스나 별도 규칙 엔진을 만들지 않는다.

```text
화면 / 입력
  ├─ Character 작성·개인 수정 서비스 → 기존 성장/규칙 계산 → Character 저장소
  ├─ 준비실·콘텐츠 서비스 → 기존 검증/카탈로그 → 캠페인 저장소
  └─ Session 명령 → Host Table runtime → 규칙 계산 → 원자적 commit
                                            ├─ 지속 기록/저장 확인
                                            ├─ 수신자별 화면 변경/결과
                                            └─ 소유자 Character 반영
수신자의 확정 결과 → 화면 구독 / 연출 (게임 상태를 변경하지 않음)
```

- AppSnapshot 호환은 경계 하나에서만 유지하고 종료 조건을 적는다. 새 기능은 MockAdapter에 추가하지 않는다.
- 새 테이블의 무조건 전체 상태 방송은 금지. Host 내부 state와 플레이어가 받을 projection/이벤트를 구분한다.
  DM snapshot에는 비공개 정보를 포함할 수 있지만 플레이어 payload에는 처음부터 없어야 한다.
- 명령에 ID·권한·대상 revision을 포함하고 Host에서 검사한다. client 입력의 결과/비용을 신뢰하지 않는다.
- durable commit → 수신 확인 순서를 고정한다. 재접속 커서와 저장 확인은 별도로 추적한다.
- 전체 상태 복원 undo는 오프라인 초기 실험으로 한정해 검토한다. 다중 소유자 저장에선 취소/보정을 새 이벤트로 기록한다.
- 초기에 단일 명령 처리열로 순서를 보장한다. 반응 대기 중에는 읽기/개인 UI와 무관 명령의 허용 범위를 명시한다.
  무관함을 증명하지 못한 공유 상태 변경은 순서대로 처리한다.

## 10. 공사 순서 — 커널 기능 목록보다 완결되는 사용자 여정

| 단계 | 실제 완료할 여정 | 이전 T2와 관계 |
| --- | --- | --- |
| P0 기반 | 기존 저장본 fixture·백업·오류 사례를 확보. 생성→개인 저장→Host 입장→사용량 변경→개인 반영의 작은 연결 실험. 비공개 payload/중복/재접속 계약 검증 | T2-01 검토 + T2-03의 위험 부분을 앞으로 당김 |
| P1 개인 캐릭터 | 저장본 열기→HP/슬롯/가방 수정→앱 재시작→변경 유지. 새 시트·가방의 첫 작동 버전 | 기존 계획의 누락 영역 |
| P2 생성과 성장 | 새 캐릭터 생성→선택 변경→초안 재시작→레벨업→행동 갱신→확정 저장 | 기존 계획의 누락 영역 |
| P3 짧은 실전 | 그 캐릭터로 Host+P1+P2 입장→공격/주문/반응→버리기/투척/엎드리기→되돌리기→끊김 복구. 핵심 VFX 포함 | T2-02/03/05를 작동하는 얇은 여정으로 묶음 |
| P4 준비와 캠페인 | 준비실→다중 소환/그룹→자료 공개→장면 전환→휴식/아이템 전달→세션 종료→다음 세션 | T2-04 + 기존 지속성 |
| P5 폭과 깊이 | 직업/주문/아이템 기능군을 동일 경계로 이식. 실제 회귀 시나리오와 화면 evidence 확보 | T2-06 |
| P6 교체와 배포 | 기존 저장본 이관·되돌아가기 검증, 구 adapter 경로 제거, 같은 SHA의 Windows 앱으로 최종 여정 검증 | T2-07 |

초기부터 예쁜 종합 목업만 만들거나, 모든 기능 구현을 끝낸 뒤 연결/저장을 붙이는 방식으로 진행하지 않는다.
각 단계에서 읽기 가능한 현재 상태·실행 명령·실패 증거·다음 한 가지를 기록한다.
기존 구조를 문자열로 고정한 테스트는 변경 의도를 분류한 뒤 행동 검증으로 대체한다. 실패를 감추기 위해 삭제하지 않는다.

### 저장본 보호와 전환

기존 저장소를 직접 덮어쓰며 새 모델을 실험하지 않는다. fixture와 백업 복사본으로 versioned importer를 먼저 검증한다.
지원하지 않는 필드/출처/아이템은 보존하고 보고한다. 양방향 읽기를 입증하지 못한 포맷을 ‘롤백 가능’이라 하지 않는다.
한 캠페인/세션에는 하나의 런타임만 사용한다. 실행 중 V1/V2를 전환하거나 두 엔진이 같은 파일에 쓰지 않는다.
기존 branch/PR은 이번 문서 때문에 삭제·종료·자동 병합하지 않는다. 새 통합은 검증된 범위로 단계별 PR을 만든다.

## 11. 수락 시나리오

1. 개인 상태에서 HP, 슬롯, 자원, 물약 수량, 충전을 수정하고 저장 실패/재시작에도 값이 일관됨.
2. 생성 중 배경 변경으로 무효가 된 선택만 다시 요구하고, 새 행동·아이템이 시트와 세션에서 일치함.
3. 레벨업 도중 취소/재시작/저장 실패에서도 이전 캐릭터 보존. 확정 후 새 능력이 사용 가능함.
4. 근접 공격 빗나감→물러남→기회공격 선택; 이탈 시 억제. 거리 입력 없이 수행됨.
5. 검 놓기→다른 물건 꺼내기→임의 물건 투척→DM 판정→엎드리기→일어나기를 화면에서 수행.
6. 물건 전달/공유 보관함/사용의 중복 요청, 연결 끊김, 소유자 오프라인에서 복제·유실 없음.
7. 반응행동 결과가 본 공격에 정확히 반영되고, 주사위/이펙트는 상태를 다시 변경하지 않음.
8. 숨은 NPC/DM Only 굴림이 플레이어 wire payload·기록·VFX 어디에도 나타나지 않음.
9. 여러 피해·치유가 연속 도착해도 결과를 구별할 수 있고 다음 입력이 연출을 기다리지 않음.
10. 세션 종료→개인 시트→다음날 재접속까지 HP/소비 자원/아이템·캐릭터 revision이 일치함.

## 12. 소유자 결정 기록 — 2026-09-09 확정

| ID | 확정 내용 | 반영 |
| --- | --- | --- |
