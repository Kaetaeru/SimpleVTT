# 캠페인·테이블 검증 시나리오 (M4, Roll20 모델)

`ROLL20_MODEL.md` 기준. 자동 시나리오는 `scripts/capture-client-table.mjs`(같은 PC의 DM 탭 + 플레이어 탭, BroadcastChannel)와 `tests/client/table.test.ts`(호스트 + 클라이언트 시뮬레이션)가 돌린다. 기대 결과는 두 탭 **모두**에서 확인한다. LAN·하마치는 exe에서 §B로.

## A. 자동 (두 탭, 한 PC)

| # | 시나리오 | 단계 | 기대 결과 | 자동화 |
| --- | --- | --- | --- | --- |
| SC-1 | 캠페인 만들기 | DM: 캠페인 화면 → 이름 → "새 캠페인" | 상세 화면. 참가 코드 `tab:camp_…-CODE`가 보이고 복사·"코드 다시 만들기"가 있다 | capture 28, table.test |
| SC-2 | 게임 시작 | DM: "게임 시작" | 테이블이 열리고 같은 코드가 헤더에 보인다. exe면 `IP:41230-CODE` 코드들이 앞에 온다 | capture |
| SC-3 | 참가 코드로 입장 | 플레이어: 캠페인 화면 → 코드 붙여넣기 → 입장 | 두 탭의 참가자 줄에 서로가 보이고, 채팅에 "지연 입장 (처음)", 플레이어의 "참가한 캠페인"에 카드가 생긴다 | capture 29 |
| SC-4 | 채팅과 굴림 | 양쪽에서 말하기, `[[1d20+2]]` 인라인, `/roll 2d6+3 # 피해` | 메시지가 양쪽에 같은 순서로, 인라인은 `[값]`으로, 굴림은 주사위 카드(눈·수정치·합)로 양쪽 같은 값 | capture 30 |
| SC-5 | 귓속말·GM 굴림·서술 | `/w gm …`, `/gmroll 1d20`, DM `/desc …`, 플레이어 `/desc` | 귓속말은 보낸 사람·대상·GM만, GM 굴림은 굴린 사람과 GM만, `/desc`는 GM만 쓸 수 있고 거절 알림이 뜬다 | capture 31, table.test |
| SC-6 | 내보내기와 다시 허용 | DM 캠페인 설정에서 "내보내기" → "다시 허용"; 플레이어 "다시 입장" | 내보내진 순간 플레이어는 거절 화면, 다시 허용 뒤 같은 코드로 들어오면 지난 채팅이 그대로 | capture 32, table.test |
| SC-7 | 보관함과 재시작 | DM "게임 닫기" → 캠페인 상세 → "게임 시작" | 플레이어는 닫힘 표시. 상세의 채팅 보관함 개수가 맞고, 다시 시작한 테이블에 지난 채팅이 보인다 | capture 33–34 |
| SC-8 | 잘못된 코드 | 코드만 다른 문자열로 입장 | "참가 코드가 맞지 않습니다" | capture 35, table.test |
| SC-9 | 코드 다시 만들기 | DM "코드 다시 만들기" → 플레이어가 옛 코드로 입장 | 거절. 새 코드로는 입장 | table.test(코드 고정) + 수동 |
| SC-10 | GM 승격 | DM이 참가자를 "GM으로" | 승격된 사람이 귓속말 전부와 GM 굴림을 보고 `/desc`를 쓸 수 있다 | table.test |
| SC-11 | 재접속 | 플레이어 탭 새로고침 → "다시 입장" | 놓친 채팅만 보충되고(권한 밖 귓속말 제외) 참가자 줄이 다시 켜진다 | table.test(리플레이) |
| SC-12 | 사칭 방지 | 코드를 아는 참가자가 호스트의 사용자 id로 hello | 거절(호스트 비밀 없음) | table.test |
