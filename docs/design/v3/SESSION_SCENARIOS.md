# 멀티세션 검증 시나리오 (M4)

세션 기능은 아래 시나리오로 검증한다. 각 시나리오는 "누가 · 무엇을 · 기대 결과"이며, 자동화된 것은 `scripts/capture-client-session.mjs`(같은 PC의 두 탭, BroadcastChannel)와 `tests/client/session.test.ts`(호스트 + 클라이언트 시뮬레이션)가 돌린다. LAN·하마치는 exe에서 수동 체크리스트(§B)로 확인한다.

## A. 자동 (두 탭, 한 PC)

| # | 시나리오 | 단계 | 기대 결과 | 자동화 |
| --- | --- | --- | --- | --- |
| SC-0 | 캠페인 만들기 | DM 탭: 세션 로비에서 "새 캠페인" (또는 캠페인 화면) | 캠페인이 목록에 생기고 로비의 캠페인 선택에 잡힌다 | capture |
| SC-1 | 캠페인에서 세션 열기 | DM 탭: 캠페인 선택 → "세션 열기" | 세션 제목이 캠페인 이름, 초대 코드 `tab:sess_xxxx-ABC234`가 보이고 복사 버튼이 있다. DM이 참가자 목록에 "DM"으로 뜬다 | capture 28 |
| SC-2 | 참가와 캐릭터 데려오기 | 플레이어 탭: 초대 코드 붙여넣기 → 참가 → 라이브러리 캐릭터 선택. DM도 캐릭터 데려오기 | 두 탭의 파티 목록이 같고(둘), 참가자 목록에 서로가 보인다. 플레이어 카드에 "나" 표시 | capture 29 |

| SC-7 | 되돌려 쓰기 | 플레이어가 "나가기" 후 라이브러리에서 같은 캐릭터를 열기 | 세션에서 바뀐 HP·기록(DM 피해 포함)이 라이브러리 시트에 그대로 | capture 33 |

| SC-12 | 호스트 종료 | DM "세션 닫기" | 플레이어 탭 상태가 "닫힘", 조작이 거절되고 라이브러리에는 마지막 상태가 남음 | 수동 |

## B. 수동 체크리스트 (exe, LAN·하마치) — S3 뒤에

| # | 시나리오 | 확인 |
| --- | --- | --- |
| LAN-1 | 같은 공유기 | 호스트 exe "세션 열기" → IP 후보 목록에 LAN IP 표시 → 플레이어 exe에서 `192.168.x.x:41230-TOKEN` 입력 → 입장 |
| LAN-2 | 하마치 | 두 PC가 같은 하마치 네트워크 → 호스트 IP 후보에 25.x.x.x 표시 → 플레이어가 그 코드로 입장. 첫 실행 시 Windows 방화벽 허용 팝업에서 허용 |
| LAN-3 | 방화벽 차단 | 호스트 방화벽에서 포트 차단 → 플레이어 화면에 "호스트에 연결하는 중…"과 안내 문구, 타임아웃 뒤 실패 메시지 |
| LAN-4 | 모듈 불일치 | 플레이어에 PHB 보충 모듈 미설치 → 입장 시 "호스트에 있는 모듈 X를 설치하세요"와 설치 버튼 → 설치 후 입장 |
| LAN-5 | 끊김·복구 | 플레이어 네트워크를 30초 끊었다 붙임 → 자동 재접속, 놓친 기록 복구 |
| LAN-6 | 호스트 재시작 | 호스트 exe 종료 후 같은 캠페인으로 다시 열기 → 플레이어가 캐릭터를 다시 데려오면 플레이어 사본이 반영(D67) |

## C. 시나리오를 추가할 때

- 자동 시나리오는 두 탭 스크립트에 단계를 더하고 스크린샷 번호를 잇는다. 기대 결과는 두 탭 **모두**에서 확인한다(한쪽만 보면 동기화 버그를 놓친다).
- 규칙 수준(시트 조작 결과)은 `session.test.ts`에 넣는다: 브라우저 없이 호스트와 클라이언트 두 개를 시뮬레이션한다.
