# 자동화 감사 — 아직 사람이 계산하는 것 (2026-09-17)

목표: 플레이어는 **시전·공격·선택**만 하고, 나머지 계산(피해, 내성, 상태, 지속, 반복, 보정)은 앱이 한다.
범위: SRD 5.2.1 주문 339개 + PHB 2024 보충 주문 52개, SRD 클래스·서브클래스 특성, 재주(SRD 17 + 보충 58), 종족 특성, 보충 서브클래스 36개(특성 178개), 워락 기원술, 메타매직.
방법: 카탈로그 전체를 스크립트로 훑어 실행 정의·효과 계약·반복(`sustain`)·명중 후(`onHit`)·소환·계약 질문(`adjudication.request`)을 분류하고, 주문 설명의 반복·보정·상태 문구와 대조한 뒤 핵심 항목은 코드에서 직접 확인했다. 휴리스틱이 섞인 분류라 개수는 대략이다.

## 1. 구조적 빈틈 (엔진이 아직 못 하는 계산) — 우선순위 순

### A. 대상에게 건 효과가 굴림에 반영되지 않음
효과는 대상 시트·토큰에 이름과 상태로만 남는다. "그 대상을 향한/그 대상이 하는 굴림"을 바꾸는 계산이 없다.
- 억압(-1d4), 요정 불꽃(대상 향한 이점), 유도 화살(다음 공격 이점), 잔혹한 모욕(다음 공격 불리), 정신 파편(-1d4), 신경 정지(-1d6), 저속화(AC·속도·행동 제한), 서리 광선(속도 -10), 냉랭한 접촉(회복 불가), 전격의 손아귀(반응 불가), 별빛 도깨비불·빛나는 강타(대상 향한 이점)
- 사냥꾼의 표식·사술: 추가 1d6이 **표식 대상이 아니라 모든 무기 공격**에 붙고, 대상이 쓰러졌을 때 표식 옮기기는 새 시전처럼 처리됨
- 방어형: 흐려짐(나를 향한 불리), 거울 분신(d20 가로채기), 성역(공격자 지혜 내성), 점멸(매 턴 d6)
- 특성: 분쇄자·참격자(다음 턴까지 이점/불리), 분석한 공격, 정밀한 사냥꾼, 붙잡을 수 없음

### B. 턴 시작/끝 자동 처리(틱)가 없음
대상 턴 끝의 내성 반복(인간형 포박 등)은 있지만, **매 턴 피해·구역 피해·누적 내성**은 버튼(↻)이나 손으로 한다.
- 구역 지속 피해: 영혼 수호자, 달빛 광선, 죽음구름, 검은 촉수, 화염 장벽, 가시 성장, 곤충 무리, 단검 구름, 하다르의 굶주림 — 들어오거나 턴을 시작할 때마다 ↻을 눌러야 함
- 대상 지속 피해: 작열하는 강타(불붙음), 휘감는 일격(구속 중 1d6), 환영 살해자, 기괴, 산성 화살류
- 누적 내성: 전염(3회), 육신 석화(3회), 권능어: 충격

### C. 피해·치유 보정 특성이 카드에 안 들어감 ("카드에서 DM이 더합니다")
- 고통스러운 폭발(기원술 대상 소마법은 저장되지만 피해에 매력 수정치 미반영), 강화된 방출술, 강력한 주문 시전(드루이드 원소의 격노), 원소 친화력(저항만, 피해 +매력 없음), 강력한 소마법(빗나가도 절반)
- 회피 기동(몽크·로그: 민첩 내성 성공 0 / 실패 절반)
- 생명의 제자(+2+주문 레벨), 최고의 치유(최대값), 치유사 재주(1 재굴림)
- 적 학살자(표식 d10), 과부하(최대 피해 + 반동)

### D. 명중 후 창에 아직 없는 "명중 시" 선택
- 축복받은 일격(신성한 일격 1d8), 광휘의 일격(팔라딘 11, 자동 +1d8), 거상 학살자, 우월한 사냥꾼의 먹잇감
- 교활한 일격·향상된/교묘한 일격(암습 주사위를 포기하고 효과·내성), 잔혹한 일격 효과
- 충격의 일격(기 소비 후 **대상 건강 내성**이 자동 굴림 아님), 열린 손 기술(효과·내성), 진동하는 손바닥, 강화된 타격(유형 변경)
- 워락 섬뜩한 강타·생명 흡수 칼날 등 기원술 무기 효과

### E. 반응 계기 알림이 없는 것
방패·주문 차단·가로막기·기회 공격만 창이 뜬다.
- 지옥의 책망(피해 받을 때), 깃털 낙하(추락), 불가사의한 회피(피해 절반), 방패 달인(내성 성공 시 0), 보호 재주, 파수꾼(조건), 전투 시전자(기회 공격 대신 주문), 에너지 저항의 은총 반격, 화염 방패·아가티스의 갑주 반격 피해

### F. "굴릴 때 선언" 이점·불리가 자동이 아님
- 위험 감지(민첩 내성), 야성의 본능(이니셔티브), 비범한 운동선수, 믿음직한 재능(9 이하 → 10)
- 종족: 요정 혈통(매혹 내성 이점), 노움의 교활함, 용감함(공포), 하플링 행운(1 재굴림), 행운아 재주(점수)

### G. 사용형 능력의 실제 효과가 없음 (풀만 소비)
- 종족: 브레스 무기(내성 피해 카드 없음), 치유의 손, 천상의 현현, 거인 혈통 능력들, 아드레날린 분출(임시 HP), 끈질긴 인내(0 HP 대신 1 자동 아님)
- 클래스: 신성 변환 선택지(신성한 불꽃·언데드 퇴치·팔라딘 맹세 효과), 야생 변신(야수 스탯 교체 없음 — 임시 HP만), 바드의 영감(아군이 쓸 때 굴림에 더해지지 않음), 메타매직 10종(쌍둥이 대상 추가·신속 추가 행동·강화 재굴림·고양 불리 등 전부 수동), 섬뜩한 대가·마력의 현신·비전의 신격화
- 무료 시전 계열: 주문 숙련·대표 주문, 요정/그림자의 손길, 의식 시전자, 주문 회상의 은총 — 시전 방식에 "무료"가 자동으로 안 뜨는 경우가 있음

### H. 시트에 자동 반영 안 되는 성장
- 심신일체(민첩·지혜 +4), 미끄러운 정신(지혜·매력 내성 숙련), 학자(전문화), 추가 숙련
- 항상 준비 주문 수동 추가: 용의 주문, 마귀 주문, 마법 발견, 방출술 전문가

### I. 복잡 주문 (별도 규칙 엔진 필요)
- 스탯 교체: 변신, 진정한 변신, 형상변화, 동물 형상, 물체 조종, 거대 곤충
- 표·선택 효과: 혼란(d10 행동표), 무지개 분사·무지개 벽(색별), 명령(명령어별), 저주 부여(선택지), 용의 숨결(대상에게 브레스 행동 부여), 광기의 왕관(대상 조종 공격), 강제 결투
- 복합 부가: 번개 화살·가시 비의 주변 피해, 지진, 시간 정지, 소원, 권능어: 충격
- 다른 이에게 행동을 주는 것: 가속(추가 행동 제한), 영웅들의 축연, 신속한 화살통

## 2. 보충 모듈 (PHB 2024) — 규칙 데이터가 전혀 없는 서브클래스 36개

모든 특성이 설명 글뿐이다. 선택해도 시트·테이블 계산이 달라지지 않는다.

- 바바리안: 야생의 심장 길, 세계수 길, 광신자의 길
- 바드: 춤 학파, 매혹 학파, 용맹 학파
- 클레릭: 빛 권역, 속임수 권역, 전쟁 권역
- 드루이드: 달의 회합, 바다의 회합, 별의 회합
- 파이터: 배틀 마스터(기동 주사위·기동 전부), 엘드리치 나이트, 사이 워리어
- 몽크: 원소의 전사, 자비의 전사, 그림자의 전사
- 팔라딘: 고대의 맹세, 영광의 맹세, 복수의 맹세
- 레인저: 야수 조련사, 요정 방랑자, 어둠 추적자
- 로그: 비전 속임수꾼, 암살자, 소울나이프
- 소서러: 비정상 마법, 시계태엽 마법, 야생 마법
- 워락: 대요정 후원자, 천상체 후원자, 위대한 옛 존재 후원자

## 3. 제안하는 작업 순서

1. **대상 효과 엔진(A)** — "효과 소유자 = 대상, 굴림 수정 = 그 대상을 향한/그 대상의 굴림"을 계약 속성으로. 억압·요정 불꽃·유도 화살·사냥꾼의 표식 대상 한정이 한 번에 풀린다.
2. **턴 틱 엔진(B)** — 턴 시작/끝에 효과·구역의 피해와 내성을 호스트가 자동 처리.
3. **피해·치유 보정 파이프라인(C)** — 특성 계약에 `spell-damage.bonus`, `save-half.to-zero` 같은 속성을 추가.
4. **명중 후 창 확장(D)** + **반응 계기 확장(E)** — 기존 창 구조 재사용.
5. **선언형 이점 자동(F)**, **사용형 능력 카드(G)**, **시트 반영(H)** — 계약 데이터 위주.
6. **보충 서브클래스 36개 데이터 작성(2장)** — 1~5의 어휘가 생긴 뒤에야 대부분 데이터로 쓸 수 있다. 배틀 마스터 기동은 명중 후 창(D)에 의존.
7. **복잡 주문(I)** — 스탯 교체(변신류)는 소환 템플릿(D219)과 커스텀 NPC 파서로 확장 가능.

## 4. 규칙을 다 추가해도 목표가 안 되는 경우 (근본 원인)

1~3장을 전부 데이터로 채워도 "플레이어는 시전·공격만"이 성립하지 않는 곳이 있다. 규칙이 모자라서가 아니라 **앱이 모르는 사실**이 규칙의 입력이기 때문이다. 코드로 확인한 현황을 함께 적는다.

| # | 앱이 모르는 사실 | 막히는 예 | 현황 |
|---|---|---|---|
| 1 | **위치·거리** (TotM, 좌표 없음) | 화염구·영혼 수호자 범위 안 누구, 보호의 오라 10피트, 무리 전술·암습의 "아군이 곁에", 기회 공격·파수꾼, 밀치기·당기기, 가시 성장 이동 피해, 엄폐 | 대상은 클릭, 오라·곁 조건은 "표에서" 질문 |

| 4 | **플레이어의 의도·말** | 명령 단어, 암시·지배 명령, 소원, 하급 환영·요술, 물체 조종 이동, 준비 행동의 임의 계기 | 기록뿐 |
| 5 | **상대편(DM)의 결정** | 전설적 저항 사용, 몬스터 반응(받아치기), 광기의 왕관 공격 대상, 집중 유지 선택 | 창·버튼으로 DM에게 물음 |
| 6 | **몬스터 쪽 규칙** | 몬스터 특성 328개·반응 23개·글뿐인 추가 행동 58개 (무리 전술, 화염 몸 접촉 피해, 받아치기, 공포의 존재감, 삼키기), 본거지 행동 | 마법 저항·재생·전설 행동·재충전만 계산 |
| 7 | **끼어들기 순서** | "명중 뒤 피해 전"(불가사의한 회피), "피해 뒤"(지옥의 책망), 여러 반응 동시 발생 | 창 종류마다 따로 구현(방패·가로막기·명중 후) |
| 8 | **분배·선택** | 작열 광선·마법 화살·섬뜩한 방출 줄기 나누기, 연쇄 번개 2차 대상, 쌍둥이 주문 | 대상 순서대로 돌아가며 배분 |
| 9 | **데이터의 정확성** | 보충 모듈은 제3자가 만든 글, 계약을 사람·에이전트가 쓰면 틀릴 수 있음 | 검증 표시 없음 |
| 10 | **확인 창 피로** | 자동화할수록 명중 후·특성·반응 창이 늘어 "시전만"과 반대 | 일부만 항상/안 씀 설정 |

### 경우별 방법

**1. 위치·거리**
- (가) *거리 구간·구역 태그*: 토큰마다 교전 그룹(근접으로 붙은 무리)과 "가까움/멀리" 구간, 장면에 이름 붙은 구역(영혼 수호자 오라, 달빛 광선 기둥). 구역 칩에 토큰을 넣고 빼면 범위·틱·오라가 자동. TotM 유지. **추천**.
- (나) *자동 추론*: 근접 공격을 주고받으면 같은 교전 그룹으로 묶고, 이동을 선언하면 풀기. 입력 0이지만 틀릴 수 있어 (가)와 함께.
- (다) *선택형 격자·좌표*: 전투 페이지만 5피트 격자. 가장 정확하지만 TotM 정체성과 충돌.
- (라) *라운드당 한 번 묻고 기억*: "누가 영혼 수호자 안?"을 라운드 시작에 한 번 체크 → 그 라운드 틱에 사용. 현재 방식의 최소화.

**2. 시야·은신**
- (가) 크리처 상태로 **숨음/보이지 않음** 추가(숨기 판정 성공 시 자동 부여, 공격·주문 시전 시 자동 해제), 투명 상태와 함께 이점/불리 계산.
- (나) 장면 구역에 **조명·가림**(어둠, 짙은 가림) 속성 → 그 구역 안의 토큰은 자동 실명/보이지 않음 처리. 1-(가) 구역과 같은 구조.
- (다) "볼 수 있음" 요구는 기본 참으로 두고 DM이 예외 표시 (현실적 기본값).

**3. 턴당 횟수** — 추가만 하면 된다(순수 엔진 누락).
- 호스트 트래커 턴에 `usedThisTurn[규칙 키]` 원장, 턴 시작 초기화, 명중 후 창이 이미 쓴 것은 제안에서 빼기. 트래커 밖에서는 "라운드" 개념이 없으니 비전투 시 해제.

**4. 의도·말**
- (가) 열거 가능한 선택은 **시전 시 선택 창**(용의 숨결 원소, 에너지 보호 유형, 변신 야수, 명령 5종, 저주 부여 선택지) → 선택 결과를 규칙으로 계산.
- (나) 열거 불가한 것(암시 문장, 소원, 환영 모양)은 **자동화 대상 아님**으로 명시하고 카드에 "DM 판정" 배지. 억지로 자동화하지 않음.
- (다) 준비 행동: 계기를 자유 문장으로 적고, DM(또는 계기 당사자 화면)에 "계기 발생" 버튼 → 누르면 준비한 행동 자동 실행.

**5. 상대편 결정**
- (가) DM 정책 설정: 전설적 저항 "실패하면 자동 사용 / 매번 묻기", 몬스터 반응 자동 사용 여부 — 명중 후 설정(D199)과 같은 방식.
- (나) 몬스터 AI 기본값(가장 가까운/가장 약한 대상) 제안 + DM 한 번 클릭.

**6. 몬스터 규칙**
- (가) SRD 몬스터 329마리 특성·반응을 **계약 데이터로 작성**(플레이어 쪽과 같은 어휘 재사용). 양이 많지만 반복 패턴(무리 전술, 접촉 피해 오라, 받아치기, 공포의 존재감)이 몇십 종으로 수렴.
- (나) **패턴 사전**: 특성 이름·원문 패턴 → 표준 계약 템플릿 자동 매칭(예: "Pack Tactics" → 교전 그룹 아군 있으면 이점). 커스텀 NPC JSON에서도 `traits: [{ "pattern": "pack-tactics" }]`.
- (다) 전투에 자주 나오는 몬스터부터(CR 5 이하 상위 50) 우선.

**7. 끼어들기 순서**
- (가) 공격·주문 해결을 **단계 이벤트**로 통일: 굴림 전 → 명중 판정 후 → 피해 계산 후 → 피해 적용 후 → 턴 끝. 각 단계에서 계약의 반응을 모아 한 창에 순서대로(현재 창 3~4종을 하나의 파이프라인으로).
- (나) 여러 반응이 동시에 나면 DM 우선순위 규칙(피격자 → 아군 → 적) 고정.

**8. 분배·선택**
- (가) 다중 줄기 주문은 시전 창에서 **대상별 개수 슬라이더**(기본: 균등/한 대상 몰기).
- (나) 연쇄 번개·쌍둥이 주문: 주 대상 뒤 "추가 대상" 단계.

**9. 데이터 정확성**
- (가) 항목마다 **자동화 등급 배지**(자동 / 부분 / 수동)를 시트·주문 목록·카드에 표시 — 사용자가 어디를 믿으면 되는지 앎.
- (나) 계약에 `verified` 표시 + 시험: 대표 캐릭터·주문마다 "기대 결과" 시험을 자동 생성(현재 R-시험 방식).
- (다) 에이전트 작성 가이드(NPC·아이템 가이드처럼)로 계약 JSON 작성 → 앱이 검증 경고.

**10. 확인 창 피로**
- (가) 모든 창에 **항상/안 씀/묻기** 기본값 + 캐릭터 생성 시 "자동 모드(최선 선택 자동)" 일괄 설정.
- (나) 한 턴에 뜬 창을 **한 장으로 묶기**(명중 후 + 특성 + 반응 후보).
- (다) "자동 결정" 규칙: 손해 없는 선택(추가 피해·회복)은 묻지 않고 적용, 자원을 쓰는 것만 묻기.

### 결론
- 3·8·10은 **추가만 하면 된다**.
- 1·2·7은 **구조를 먼저 바꿔야** 한다(구역/교전 그룹, 숨음 상태, 단계 이벤트). 이걸 안 하면 A·B·E를 다 채워도 "표에서" 질문이 남는다.
- 4·5는 **완전 자동이 원리상 불가**하다. 목표는 "선택 한 번 + 나머지 자동"으로 재정의하는 것이 맞다.
- 6·9는 **양의 문제**다. 패턴 사전과 등급 배지로 우선순위와 신뢰를 관리한다.

## 5. 결정한 조합과 그 조합에 남는 구멍 (2026-09-17)

### 5-2. 결정별 구멍
**1. 범위 다중 선택 + 효과 창 들어감/빠져나감**
- *무리 전술·암습의 "아군이 대상 곁에"는 구역이 아니라 두 크리처 사이 관계.* 카드의 구역 창으로는 "누구 곁"을 못 담는다. → (가) 대상 카드에 "곁에 있는 크리처" 창 (나) 근접 공격을 주고받은 쌍을 그 라운드 동안 "곁"으로 자동 기록 + 수동 해제 (다) 공격할 때 "아군이 곁에" 체크(현행). 추천 (나)+(가).
- *들어감이 실제로 일으켜야 하는 일.* 영혼 수호자·달빛 광선·가시 성장은 "들어올 때/턴을 끝낼 때", 턴당 한 번. 들어감 버튼이 곧바로 피해 판정을 내고 그 크리처·구역의 턴당 사용을 기록해야 한다(4번 원장과 연결). 턴 끝에 안에 있으면 자동 판정(턴 틱).
- *움직이는 오라.* 영혼 수호자·보호의 오라는 시전자를 따라 다닌다. 시전자가 이동하면 멤버십이 바뀌는데 앱은 모른다. → (가) 시전자가 이동을 선언하면 해당 오라 멤버십 확인 창 한 번 (나) 오라는 기본 "모두 유지", DM만 빼기.
- *몬스터 쪽 누르기는 DM 몫.* → 구역 창에 다중 선택 넣기/빼기, 라운드 시작 일괄 확인.
- *이동 거리 기반 규칙은 여전히 불가.* 가시 성장(5피트마다 2d4), 돌격자·쾌속, 밀려난 뒤 구역 이탈, 파수꾼 속도 0. → 이동 선언에 피트 수 입력(선택) → 그 규칙만 계산, 없으면 DM 판정 표시.
- *사거리·장거리 불리.* 좌표가 없어 계산 못 함 → 현행대로 "적용 안 함"을 규칙 편차로 명시.

**2. 숨음/보이지 않음 자동**
- *보는 쪽마다 다름.* 한 적에게는 숨고 맹안시·진시야가 있는 적에게는 보인다. → (가) 전역 상태 + 보는 쪽 감각 예외 자동 (나) 쌍 단위 상태. 추천 (가).
- *해제 계기 일부는 관찰 불가.* 공격·시전은 자동 해제, 소리·엄폐 이탈·적의 수색은 선언 필요 → 수색 행동 자동 판정 + 수동 해제 버튼.
- *어둠·짙은 가림은 구역 문제.* 1번 구역 창과 같은 구조로 처리.

**3. 단계 이벤트**
- *한 턴 묶기(6-나)와 순서 충돌.* 반응은 그 단계에서 결정돼야 다음 단계로 간다 → 묶기는 같은 단계 안의 선택만.
- *반응에 대한 반응.* 주문 차단에 주문 차단, 기회 공격 뒤 파수꾼 → 깊이 제한과 순서 규칙.
- *몬스터 반응.* 9번 데이터가 없으면 받아치기 등은 파이프라인에 못 올라옴.

**4·5. 턴당 횟수·분배**
- 턴당 원장은 트래커 턴 기준 → 트래커 밖에서는 제한을 적용하지 않음을 명시.
- 줄기를 나누면 줄기마다 명중 후 창이 생김 → 줄기 결과를 모은 뒤 한 번의 명중 후 창(대상별 체크).

**6. 항상/안 씀/묻기 + 묶기**
- *매개변수가 있는 선택은 "항상" 불가.* 슬롯 레벨, 교활한 일격 효과, 영감 주사위 대상 → 캐릭터별 기본 매개변수(가장 낮은 슬롯 등)를 두면 가능.
- *자동 모드의 "최선".* 자원을 쓰는 선택의 최선은 상황 판단 → 자동 모드는 자원 없는 이득만.

**7. 열거 불가만 "DM 판정" (나만 채택)**
- *열거 가능한 선택까지 자동화에서 빠진다.* 용의 숨결 원소, 에너지 보호 유형, 변신할 야수, 명령 5종, 사술 능력치, 원소 무기 유형, 거대화/축소화, 시각/청각 박탈, 저주 부여, 야생 변신 형태 — 고르기만 하면 계산 가능한데 (나)만으로는 DM 판정이 된다 → 시전 시 선택 창(가)도 함께 채택 권장.

**8. DM 정책**
- 정책은 자원 사용(전설적 저항)만 풀고, 몬스터의 구역 이동·대상 선택은 여전히 DM 클릭 → 1번 일괄 조작과 함께.

**9. 몬스터 계약 데이터 (가만 채택)**
- *양과 반복.* 같은 패턴(무리 전술 등)을 몬스터마다 따로 쓰면 수정이 흩어짐 → 공통 패턴은 공유 계약 하나를 참조(`traits: [{ "use": "pack-tactics" }]`).
- *커스텀 NPC·보충 몬스터.* 커스텀 NPC JSON의 특성은 글뿐 → 같은 참조 필드 추가.

**10. 검증됨 표시 + 기대 결과 시험 (나만 채택)**
- *테이블에서 안 보임.* 배지 없이면 어느 결과가 자동이고 어느 게 빠졌는지 모름 → 최소한 카드에 "수동 처리 필요" 한 줄 권장.
- *보충 모듈은 저장소 밖.* 원문을 커밋할 수 없음 → 시험은 합성 스텁, 사용자 파일은 로컬 검증 스크립트로 따로.

## 6. 원칙: 앱이 모르는 사실은 "상황 버튼"으로 (2026-09-17 결정)

추가 결정(소유자): 앱이 관찰할 수 없는 사실(이동 거리, 구역 출입, 곁, 시야 등)은 **그 규칙이 걸린 상황에서 전용 UI를 띄우고 버튼으로 입력**한다(예: 가시 성장 안에 있으면 "5피트 이동함" 버튼). 5-2의 권장안도 채택: 7 = 시전 시 선택 창 추가, 10 = 카드에 "수동 처리 필요" 한 줄, 9 = 공통 패턴 참조.

### 6-1. 버튼 방식이 잘 되려면 필요한 규칙
1. **언제 뜨나(계기)**: 버튼은 앱이 이미 아는 상태에 붙어서만 뜬다 — 구역 멤버십, 켜진 효과, 트래커의 현재 턴, 방금 난 카드. 계기가 없는 사실(아무 조건 없이 "이동했나?")은 묻지 않는다.
2. **어디에 뜨나**: 팝업이 아니라 해당 크리처의 턴 패널·카드의 **상황 줄**에 상주. 사건이 남의 턴에 일어나면(밀려남, 오라에 들어옴) 움직인 쪽 조종자와 DM 둘 다에게.
3. **기본값**: 흔한 경우는 누르지 않아도 맞게 — "범위 안·보임·이동 안 함"이 기본, 버튼은 예외 입력. 기본값이 결과를 바꿀 때만 카드에 "기본값 적용: 보임" 표시.
4. **결과가 없는 버튼은 안 띄움**: 누르면 계산이 바뀌는 규칙이 있을 때만.
5. **되돌리기**: 버튼 입력도 카드 하나 — 잘못 누르면 되돌림(5-1의 연쇄 되돌리기 필요).
6. **DM 전용 버튼**: 숨겨진 사실(보이지 않는 적의 위치, 함정 발동)은 DM 화면에만.

### 6-2. 버튼 방식에 남는 구멍
| 구멍 | 예 | 방법 |
|---|---|---|
| **안 누르면 적용 안 됨(신뢰)** | 가시 성장을 걸어서 지나가고 "이동함"을 안 누름, 오라 빠져나감을 늦게 누름 | 결과가 불리한 버튼은 DM 화면에도 같이 뜸 + 턴 끝에 "안 누른 상황 버튼" 요약 한 줄 |
| **버튼이 쌓임** | 오라 3개 + 구역 2개 + 숨음 + 곁 → 턴 패널이 버튼으로 가득 | 상황 줄은 활성 계기만, 계기별로 접기, 같은 종류 묶기(구역 하나에 "들어감/나감/5피트 이동") |
| **누른 시점이 늦음** | 달빛 광선에 들어간 뒤 공격부터 하고 나중에 "들어감" | 되감기는 안 함 — 누른 시점에 계산하고 카드에 "뒤늦게 입력" 표시 |
| **연쇄 사건** | 천둥파동에 밀려 가시 성장 안으로, 밀려나서 오라 밖으로, 이동해서 기회 공격 | 강제 이동 카드가 "밀려남 N피트" 뒤에 그 크리처의 상황 버튼(구역 들어감/나감)을 바로 띄움; 이동 버튼은 "곁" 쌍을 보고 기회 공격 창 제안 |
| **거리 단위** | 가시 성장 험지(이동력 두 배), 대형 크리처, 10피트 넘는 이동 | 버튼은 5피트 단위 + 직접 입력; 험지는 구역 속성으로 자동 두 배 |
| **여러 사람이 동시에** | 두 플레이어가 같은 적을 같은 구역에 "들어감" | 호스트에서 크리처·구역·턴당 한 번으로 멱등 처리 |
| **범위 거리 관계(5피트 넘는)** | 바드의 영감 60피트, 보호의 오라 10피트, 30피트 안 아군 | 기본 "범위 안" + 카드의 "범위 밖" 버튼 |
| **선택지가 동적** | 변신 야수(대상 레벨 이하 CR), 야생 변신 형태, 소환 형태 | 선택 창이 컴펜디움에서 조건으로 걸러서 제시 |
| **선택 뒤 행동 규칙** | 명령 "도망쳐/엎드려", 공포 "원인에게서 멀어지기", 광기의 왕관 "지정 대상 공격" | 대상 턴 패널에 강제 행동 줄(예: "도망: 이번 턴 원인에게서 이동만") + DM 확인 버튼 |
| **버튼으로 안 되는 것** | 환영을 믿는지, 설득, 암시 문장, 소원, 창의적 주문 사용 | "DM 판정" 표시 유지 — 버튼으로 흉내 내지 않음 |
| **공통 패턴의 매개변수** | 무리 전술은 매개변수 없음, 접촉 피해 오라는 주사위·유형, 공포의 존재감은 DC·거리 | 패턴 참조에 매개변수(`{ "use": "touch-damage-aura", "dice": "2d6", "type": "fire" }`) + 검증 경고 |
| **"수동 처리 필요" 문구의 출처** | 어느 부분이 수동인지 앱이 알아야 함 | 계약의 질문(`adjudication.request`)·실행 정의 없는 부분에서 자동 생성, 없으면 표시 안 함 |
