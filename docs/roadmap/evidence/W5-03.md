## Host authority boundary on the verified product tree

### 1. Client intent is routed into the Host handler

At product SHA `2ac28651312f1fdbe82edb74fd13f342a8f910f7`, `src/app/connectedSessionRuntimeAdapter.ts` dispatches decoded transport messages by connected role. Only `state.mode === "host"` reaches `handleHostMessage`; only `state.mode === "client"` reaches `handleClientMessage`.

Inside the Host handler, `wire.type === "action-request"` is routed through `routeConnectedActionRequest(adapter, message, wire.request)`. If no registered ActionRequest route exists, the Host returns an `action-route-unavailable` error instead of applying state.

`src/app/connectedActionRequestPort.ts` is only the routing port: it invokes the registered Host-side handler and contains no Client-side authoritative state mutation of its own.

### 2. Authoritative action history is reserved and committed by the Host ledger

`src/app/connectedSessionProtocol.ts` owns `HostSessionLedger`. Its action-request boundary enforces the authoritative commit sequence:

- `reserveActionRequest` rejects a wrong `sessionId`;
- it de-duplicates previously committed request IDs;
- it rejects a stale `knownEventCursor` rather than accepting a Client history fork;
- it records a Host-side reservation before a request can be committed;
- `commitReservedActionRequest` rejects any request that was not reserved;
- it rejects a pending request if Host history advanced after reservation;
- only after those checks does it append the candidate to Host event history and associate the committed event with the request ID;
- `commitActionRequest` is the composed reserve-then-commit entry point.

Therefore a Client-supplied ActionRequest cannot directly append connected authoritative history, and a stale/unreserved request cannot bypass the Host ledger boundary.

### 3. Clients consume ordered authoritative events instead of authoring history

`ClientSessionReplica` in `src/app/connectedSessionProtocol.ts` maintains a private cursor and accepts only Host events for the same session in exact sequence order. It rejects session mismatch, conflicting/replayed history, event gaps, and authoritative payload-apply rejection before advancing its cursor.

`handleClientMessage` in `src/app/connectedSessionRuntimeAdapter.ts` applies connected state through Host-originated `hello-ack` / `event-batch` events via `applyConnectedClientEvents`. This is a replica-apply path, not an event-history authoring path.

Host-only scene topology commits use `HostSessionLedger.commitHostEvent` and broadcast the resulting event batch; the function explicitly ignores the operation unless connected state is Host mode with a mounted Host ledger.
