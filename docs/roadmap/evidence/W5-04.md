## Resolution presentation contract on the verified product tree

### 1. Versioned identity and authoritative payload

At product SHA `2ac28651312f1fdbe82edb74fd13f342a8f910f7`, `src/app/connectedResolutionPresentation.ts` defines the versioned schema `simplevtt.connected-resolution-presentation` v1. `ConnectedResolutionPresentationV1` fixes:

- stable `resolutionId` plus monotonic `presentationSequence`;
- `live` / `catchup` delivery identity;
- actor and ordered target identity/labels;
- the authoritative `ResolutionView`;
- an optional action presentation for non-roll/back-compatible cases;
- structured dice presentation;
- cumulative timeline; and
- `activityLink.resolutionId` back to the same resolution identity.

`isConnectedResolutionPresentation` validates schema/version, presentation identity, actor/target correspondence, authoritative dice correspondence, action-to-resolution identity, and terminal timeline consistency before accepting the payload.

### 2. Kept/discarded authoritative dice and outcome semantics

`dicePresentation` copies `resolution.authoritativeDice` as the presentation faces and derives selected/discarded indices from the already-resolved authoritative result. It preserves total/modifier data where available and validates that selected and discarded sets are unique, in range, and non-overlapping.

The envelope embeds a cloned public `ResolutionView`, so attack/check/save/damage/healing/effect outcome semantics, authoritative dice, state changes, provenance, and final outcome come from the Host result rather than a peer-side mechanics reroll. `actionFromConnectedPresentation` explicitly creates a remote Host-authority presentation-only action (`available: false`) instead of an executable local action.

### 3. Privacy/redaction boundary

The shared presentation is explicitly public (`audience.scope: "public"`). Before fan-out, `buildConnectedResolutionPresentation` removes the private interrupt object and strips private detail/provenance/state changes while an interrupt decision is pending. It applies the same redaction pattern to an unresolved concentration-save input.

`src/app/connectedActionRoutingAdapter.ts` then sends the full interrupt/concentration prompt only to the peer owning the responding Character. Therefore the public envelope does not expose the private pending choice/input while the authoritative Host retains and routes the private prompt to its owner.

### 4. Host-only fan-out and terminal catch-up without reroll

`src/app/connectedActionRoutingAdapter.ts` publishes live presentations only when connected state is Host mode with a mounted Host ledger. It builds the presentation from the Host snapshot and broadcasts `resolution-presentation` rather than asking Clients to resolve the action.

On completion, `publishCommittedResolution` builds a terminal `catchup` presentation from the same authoritative resolution, packages it with committed `ResolutionEvent` output, commits through the Host ledger, and broadcasts the resulting ordered `event-batch`. A remote request that completes without canonical `ResolutionEvent` output is rejected as `remote-action-not-event-native` instead of synthesizing Client-authoritative state.

This preserves one mechanics result for live fan-out and catch-up. The GitHub #111 implementation checkpoint independently records `terminal catch-up without reroll` for this path.

### 5. Activity and shared rendering linkage

The presentation carries `activityLink.resolutionId` equal to its `resolutionId`, and the validator enforces that equality. The same envelope carries the authoritative outcome/timeline/dice identity used by connected presentation consumers. GitHub issue #111's implementation checkpoint explicitly records Activity linkage and that shared rendering remains `VisualDiceBridge` + `CombatVfxBridge`, avoiding a second mechanics result for remote presentation.
