## How the runners work (`scripts/run-tauri-e2e-w9-02-{c,d,h}.mjs`, dispatcher switches `-W902C` / `-W902D` / `-W902H`)

- Every peer is a real Tauri process on its own data root, driven through WebDriver; player Characters are created through the production creation flow (Fighter duplicate; a Cleric and a Bard with class, cantrips, prepared spells, divine order / instrument and loadout choices), NPCs through the Campaign DM Library, Sessions through the direct-network Session screen.
- Client intents go through the production Client path (`resolveAction` in client mode → `action-request`); the DM advances the authoritative Resolution on the Host; the queued d20 is asserted from the Host's committed detail ("selected d20 N").
- Convergence is the W5-06/W5-07 AUTO contract: every Client applies the identical committed event (client entries compared with each other), HP equals the Host, and Clients' terminal presentation views equal each other. UI parity (MP-J) compares roster, Actor projection, turn economy, the normalized action bar, and the inventory between H and the owner.
- Reaction prompts use the production Bardic Inspiration follow-up (private prompt to the owner only; accepted once, then declined by the Host's authoritative timeout); concentration uses Faerie Fire and the owner's private concentration save; Ready uses the standard Ready action (armed on the owner's turn, fired as a reaction on the goblin's turn, cleared at the next own turn and when Initiative ends).
- Recovery kills processes with `taskkill` and relaunches them on the same data root; the Host is restarted while a remote action is pending and reopens the Session on its durable Campaign; a stale `knownEventCursor` is sent through the raw transport.

## Product defects found and fixed by these captures

- PR #332 — character creation wielded every starting weapon: background weapons were illegal wielded items without a slot, so a created caster could not cast any somatic spell and no inventory transaction could succeed.
- PR #333 — a connected peer applied a remote Character's resource change to its own same-id resource (silent divergence) or rejected it (`event-native apply target is missing`), leaving the observer one event behind the Host.
- PR #334 — the Host accepted off-turn remote intents while another player's projected Character held the turn, and refused to commit a reserved request when only participant events had advanced the ledger.
- PR #335 — a fired Ready action's broadcast lost the readied action's own events (the reaction spend replaced them instead of appending).
- PR #336 — after a Host restart the Clients stayed on a stale cursor forever (`invalid-event-cursor`); they now drop the stale session view and rejoin from cursor 0.
- PR #337 — an accepted d20 follow-up (Bardic Inspiration) dropped the base attack bonus from the authoritative total.
- PR #338 — a presentation that follows an interrupt stage superseded the Client's interrupt wait; DM Library NPC definitions author structured runtime stats and attacks.
- PR #339 — a projected remote Character's concentration save resolved the Host's own sheet instead of the projected sheet.
- PR #340 — Help, Dodge and Disengage committed no canonical effect event (the Host answered `remote-action-not-event-native`), and a helped attack lost its advantage in the runtime-atomic transaction.
- PR #341 — a Client rejoining a restarted Host reported "connected" before the Host had accepted its hello.
- PR #342 — the public presentation leaked the owner-private concentration save stub (target, ability, modifier source) one stage before the private prompt.
- PR #343 — a no-roll presentation whose text mentions advantage selected a die out of zero faces (index -1); every Client rejected the Host's event batch and fell one event behind for the rest of the session.
- PR #344 — an observer rejected a remote Character's item-quantity/inventory change (`event-native apply target is missing`) and fell one event behind the Host.
- PR #345 — the damage that rides on a concentration save was committed to the turn runtime only, so a later Host Undo silently did nothing.
- PR #346 — only the first projected Character an event touched received the durable write-back; a projected target's sheet drifted and a later hit on it was refused (`Character write-back drift`).
- PR #347 — a transport reconnect reported the Client as connected before the Host had accepted its hello (a rejoined Client was not yet a participant on the restarted Host).
