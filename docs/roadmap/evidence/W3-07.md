## Existing production authority reused

The shipped Phase 09 production path already implements correction/Undo as history-preserving compensation rather than destructive history editing.

- `src/app/phase09RealRuntimeAttackAdapter.ts` stores committed `ResolutionEvent` histories and performs Undo through `undoResolutionEvents(...)` plus inverse Character write-back.
- A successful event-native Undo leaves the original Activity entry in place with `reversed:true` and prepends a new correction Activity with `undoOf:<original resolution id>`; it does not delete or rewrite the original history entry.
- The Undo transaction rejects stale runtime/write-back failures before committing partial state, and reverses HP, resources/items, Action/Reaction economy, effects, and other event-owned state from the recorded events.
- `src/app/mockAdapter.ts` exposes the same visible history contract for the adapter surface: the original Activity is marked reversed and a new `correction:true` / `undoOf` Activity is appended to history.
