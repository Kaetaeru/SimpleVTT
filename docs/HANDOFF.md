## 1. 이 프로젝트가 무엇인가

D&D 5e SRD 5.2.1(2024 규칙) VTT. Tauri + React + TypeScript.

**Roll20의 모델을 따르되, 결정적으로 다른 점 하나**: 앱이 규칙을 알고 공격·주문·행동을 **반자동으로 판정한다.**
Roll20은 주사위만 굴려 주고 규칙은 사람이 안다. 이 앱은 규칙을 안다.

제품은 `client/`다. 옛 `src/` 앱은 **기록과 부품**으로만 남는다 — 생성된 SRD 카탈로그(`src/generated/*.json`)만
가져다 쓰고, 그 외에는 import하지 않는다(`npm run check:client-boundary`가 강제한다).

격자는 없다. **장면(Theatre of the Mind)이 유일한 배치**이고, 거리도 사거리도 세지 않는다(D109). 이 제약이
남은 미해결 과제 대부분의 뿌리다 — §5를 보라.

## 2. 소유자가 정한 진행 방식 (반드시 지킬 것)

대화에서 합의된 규칙들이다. 문서에 없으면 잊히므로 여기 적는다.

- **에이전트는 하나로 간다.** 서브에이전트를 띄우지 않는다.
- **조각(slice) 단위로 일한다.** 한 조각 = 코드 + 시험 + 문서(결정 기록 D번호 + 로드맵 행) + 커밋 + 푸시.
- **PR을 만들지 않는다.** 소유자가 명시적으로 요청하기 전에는 절대. 브랜치에 푸시만 한다.
- **보고는 한국어로.** 무엇을 왜 그렇게 했는지, 막힌 것이 있으면 숨기지 말고.
- **막힌 것은 조용히 건너뛰지 말고 보고한다.** 소유자의 지시다 — "그런 부분은 그냥 넘기지 말고 나한테 보고해서
  정하게 하자". 규칙 한 줄을 구현할 수 없으면, 왜 못 하는지 말하고 선택지를 내민다.
- **exe 빌드는 요청받을 때만** 한다(`npm run tauri:build`). 조각마다 굽지 않는다.
- **저장소에 들어가는 글에 모델 이름을 쓰지 않는다** — 코드 주석, 문서, 커밋 본문 어디에도. (커밋 끝의 귀속
  푸터는 하네스가 주는 별개의 것이다.)
- 커밋은 이 형태로 해 왔다:
  ```
  git -c user.name="Claude" -c user.email="noreply@anthropic.com" commit -q -F -
  ```
- 푸시 실패는 네트워크 문제일 때가 있어 지수 백오프로 재시도해 왔다:
  ```
  for d in 0 2 4 8 16; do sleep $d; git push -u origin claude/practical-newton-rye61w && break; done
  ```

### ⚠ 게이트를 동시에 돌리지 말 것

```
npm run gate:client   # 타입 + 경계 + 단위 322개   (~40초)
npm run gate:e2e      # 브라우저 캡처 17개          (~290초)
npm run gate          # 위 둘을 순서대로
```

**`gate:client`와 `gate:e2e`를 병렬로 돌리면 자원 부족으로 가짜 FAIL이 난다.** 반드시 순차로. 이걸로 한 번
속아서 없는 회귀를 쫓았다.

### Windows 로컬에서 (2026-09-17)

- `npm run gate:e2e`가 Windows에서 돈다: Playwright는 개발 의존성이고(`npx playwright install chromium` 한 번),
  러너가 Vite를 `--host 127.0.0.1`로 띄운다(Windows의 `localhost`는 ::1에만 묶여 포트 확인이 실패했다).
- 캡처 스크립트를 **단독으로** 돌릴 때는 Vite를 직접 `--host 127.0.0.1`로 띄워 둘 것(스크립트 안의 자동 기동은 IPv6 문제가 남아 있다).
- 러너가 띄운 Vite가 가끔 남는다: 1430 포트를 쓰는 node(vite) 프로세스를 끄고 다시 돌린다.
- **`git stash`를 쓰지 말 것**: E2E가 `docs/evidence/*.png`를 매번 다시 쓰므로 pop이 충돌한다.
- 이 PC에는 ecc 플러그인의 GateGuard 훅이 켜져 있어, 파일을 처음 만들거나 고칠 때마다 이유를 적으라고 막는다(작업은 된다).

### 2026-09-17 플레이 흐름 개편 (R63~R68)

소유자 지시: 세션·시트의 UI/UX를 재배치하고, 재주의 발동 방식에 맞는 직관적인 플레이 흐름을 만들 것.

- **R63 (D198)** — **명중 후 선택 창**. 암습·신성한 강타·야만적 공격자와 계약 라이더(대형 무기 달인·돌격자·관통자·
  선술집 싸움꾼)를 굴리기 전이 아니라 **명중한 뒤** 묻는다. 대상 반응 → 공격자 순. 계약 `invocation: "on-hit"`,
  프로토콜 30 `act.onhit`, 같은 주사위로 재계산(`carryDice`·`rerollOnce`).
- **R64 (D199)** — 제안마다 **매번 묻기/항상 사용/쓰지 않음**(`runtime.hitPolicy`). 신성한 강타는 항상 사용 불가.
- **R65 (D200)** — 턴 패널을 **행동/추가 행동/반응/그 밖 줄**로. 특성은 남은 횟수가 붙은 버튼(누를 것 있는 것만).
- **R66 (D201)** — 승인 창이 이 사람에게 온 프롬프트를 **최대 셋까지 쌓아** 보여 줌. 트래커·토스트가 인물을 가리지 않게.
- **R67 (D202)** — 플레이 시트가 **이름·수치 줄부터**. HP는 숫자 + 피해/회복/임시/설정 버튼, 상태는 걸린 것만.
- **R68 (D203)** — 헤더를 한 줄로: 시간·휴식은 시계 칩 아래, 참가 코드는 복사 버튼.

**설계 원칙**: 규칙은 **코드가 아니라 카탈로그**가 들고 있다. 실행기와 리졸버가 그것을 굴린다. 손으로 쓴 규칙 표는
`EFFECT_RULES` 1개, `FEATURE_ACTIVATIONS` 4개만 남았다(R49에서 63개·49개를 비웠다).

새 규칙을 넣을 때 **먼저 물을 것**: "이걸 계약 문법으로 쓸 수 있나?" 쓸 수 있으면 코드가 아니라 콘텐츠로 쓴다.
문법이 부족하면 문법을 넓히고 결정 기록에 남긴다.

## 5. 막혀서 남겨 둔 것들 — 발명하지 말 것

**중요**: 아래는 실패가 아니라 **의도적으로 남긴 것**이다. 근거 없이 "고치지" 말 것. 손대려면 소유자에게 먼저
물어야 한다.

1. **장면에 위치가 없다 (D109).** 인접·5피트·직선 10피트를 앱이 볼 수 없다. R57의 **선언 체크박스**가 소유자가
   고른 우회다 — 격자를 되살리거나 좌표를 발명하지 않는다. 비슷한 규칙이 또 나오면 같은 방식을 쓴다.

2. **명사수 · 쇠뇌 전문가 · 주문 저격수의 근거리 조항은 무효(no-op)다.** 이 앱은 그들이 없애 주는 **불리함을 애초에
   적용하지 않는다**. 그래서 이미 효력이 있는 상태이고, 계약은 질문을 던지는 대신 **그렇다고 적어 둔다**. 결과 없는
   체크박스를 만들지 않기로 한 것이다.

3. **요정의 손길 · 그림자의 손길의 학파 제한 선택**(점술/환혹, 환영/사령 1레벨 주문 하나)은 **표의 몫**이다.
   주문 색인에 **학파 정보가 없어서** 거를 수 없다. 전체 목록을 내미는 건 "표에서 고르세요"보다 나쁘다.

4. **`autofill`의 다회차 순서 문제.** 같은 재주 안에서 **앞의 선택 때문에 비로소 유효해지는 선택**(기술 전문가의
   전문화는 자기 숙련이 먼저 있어야 함)은, 둘 다 못 본 회차에서 거절된다. **엔진은 옳고** 마법사에서 순서대로
   답하면 정상이다. `tests/client/r62.test.ts`의 `withFeat`가 이 사정을 주석으로 적고 우회한다. 고칠 가치가
   있다고 보면 소유자에게 제안하되, 조용히 건드리지 말 것.

5. **덧대기 모듈은 설치 순서를 탄다.** `phb-2024.feat-config-patch`는 **보충 자료 다음에** 설치돼야 한다. 먼저
   설치하면 보충 자료의 `execution` 등이 덧대기 값을 되돌린다.

6. **계약 158/223.** 나머지는 표가 판단할 산문이다 — 탈것, 부엌, 장면이 잴 수 없는 거리. **침묵(코드가 이름조차
   모르는 것)은 0개**다. 없는 것을 있는 척하지 않는 것이 이 프로젝트의 규칙이다(D168: `execution: "descriptive"`가
   그것을 표시한다).

  `class.0.skills`. 재주 하위 선택은 `feat.<instanceKey>.<featId>.<suffix>`.
- 파이터의 기술 목록에 **조사(investigation)는 없다**. 역사(history)는 있다.
- 공격 카드는 `message.action`이지 `message.attack`이 아니다.
- 배경이 능력치를 올리므로 **피해 보너스를 상수로 박지 말고** 시트에서 유도해 비교할 것.
- E2E가 첫 스크립트에서 불안정하면 `scripts/run-client-e2e.mjs`의 `warm()` 선(先)요청을 확인할 것 — Vite 콜드
  스타트 컴파일 비용이 두 번째 스크립트의 타임아웃으로 새던 것을 이걸로 막았다.

## 8. 한 조각을 끝내는 절차

1. 코드를 쓴다. 계약으로 쓸 수 있으면 코드 대신 콘텐츠로 쓴다.
2. `tests/client/r<N>.test.ts`에 시험을 쓴다. 규칙 문장 하나에 단언 하나.
3. `npm run gate:client` — 통과할 때까지.
4. `npm run gate:e2e` — **위가 끝난 뒤에** 돌린다. 동시에 돌리지 않는다.
5. `docs/design/v3/ROLL20_TABLE_SPEC.md`에 **결정 기록 D번호**와 **§14 로드맵 행**을 추가한다.
   행 형식: `| R63 제목 ✔ | D198: 무엇을 했는지 | 단위 N개 통과(rNN.test.ts M개 새로), E2E 17개 전부 통과 |`
6. 커밋(§2의 형태) → 푸시.
7. 한국어로 보고한다. 막힌 것이 있으면 그것도.
